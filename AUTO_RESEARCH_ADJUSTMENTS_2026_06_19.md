# Auto-Research Adjustments - 2026-06-19

## Scope

This pass addressed resolver outputs that were structurally successful but missing the requested time window. The changes were kept generalized: no case-specific few-shot examples were added, and normal VP_verify mappings still take precedence over deterministic fallback behavior.

## Code Changes

- `features.py`
  - Preserves explicit time windows for precomputed/raw KPI intents instead of dropping the time metadata.
  - Normalizes current-month-till-date phrases to month-to-date metadata.
  - Normalizes `week N` to exact previous-week metadata.
  - Normalizes `month N` to exact previous-month metadata.

- `seeds.py`
  - Added `S178_raw_kpi_month_mtd` for raw KPI comparison in current month-to-date windows.
  - Added `S179_raw_kpi_week_exact` for raw KPI comparison in exact previous week-index windows.

- `api_client.py`
  - Added conservative KPI fallback candidates for revenue phrases when VP_verify does not match a highly specific service phrase.
  - Example: a phrase such as roaming financial services revenue can fall back to total revenue only after the specific candidate fails.

- `renderer.py`
  - Added narrow fallback handling when VP_verify raises during filter or duration-threshold resolution.
  - Normal successful VP_verify mappings still win.
  - Fallback currently covers common subscriber filters: handset/device, nationality, active/inactive status, prepaid/postpaid, recharge amount/count, and AON-style duration thresholds.

- `vp_logging.py`
  - Made log formatting robust for numeric/list filter values.

- Tests
  - Added renderer fallback tests for VP_verify exceptions on duration thresholds and smartphone filters.
  - Updated feature expectations for raw KPI intents that now retain time metadata.
