# VP Resolver — Changes 2026-05-04

This file documents every change made in the 2026-05-04 development session:
seed reinforcement from user-provided PARENT_CONDITIONs, seed source tagging,
and SQLite-backed VP_verify caching.

---

## 1. New file — `reinforcer.py`

### Purpose

When the pipeline returns `NO_CANDIDATES` or `NO_STRONG_MATCH`, the user can
provide the correct `PARENT_CONDITION` string directly. `reinforcer.py`
reverse-engineers that condition into a new seed and persists it so future runs
find it automatically.

No API calls are made during extraction — the column names are already resolved
inside the condition. Regex parsing is sufficient.

### Public API

```python
from reinforcer import (
    parse_parent_condition,   # condition str → structured dict
    build_seed_template,      # parsed dict  → template string with placeholders
    derive_selection_signature,# parsed dict  → selection_signature dict
    make_reinforced_seed,     # (input, condition) → full seed dict
    save_reinforced_seed,     # seed dict → appends to reinforced_seeds.json
    DuplicateSeedError,       # raised when template/condition already exists
)
```

### Key design decisions

**Template uses placeholders, not concrete column names.**
`COMMON_Event_Date >= CurrentMonth-3MONTHS AND SUM(COMMON_Data_Volume) > 5000`
becomes:
```
{date_col} >= CurrentMonth-{N}MONTHS AND SUM({kpi_col}) ${operator} ${value}
```
The VP_verify API is still called on future runs (same as catalog seeds) to
resolve `{kpi_col}`.

**Attribute filters and AON thresholds are kept verbatim.**
`Profile_Cdr_Handset_Type = smartphone` stays in the template as-is.

**`selection_signature` is derived deterministically** from the parsed dict,
compatible with `score_seed()` / `hard_reject_seed()` in `selector.py`.

**`source = "reinforced"` is set at construction time** on the seed dict itself
(not injected later by `load_seeds()`).

### Regex coverage

| Pattern | Example |
|---------|---------|
| Month lower bound | `EVNT_DT >= CurrentMonth-3MONTHS` |
| Month equality | `EVNT_DT = CurrentMonth-1MONTHS` |
| Month upper bound | `EVNT_DT < CurrentMonth` |
| Time DAYS/WEEKS | `EVNT_DT >= CurrentTime-30DAYS` |
| SUM | `SUM(col) > 1000` |
| MAX | `MAX(col) > 1000` |
| COUNT_ALL (primary) | `COUNT_ALL(col) > 5` |
| COUNT_ALL (presence) | `COUNT_ALL(col) > 0` (fixed, not parameterized) |
| COUNT_ALL (constraint) | `COUNT_ALL(col) = 2` (secondary alongside SUM/MAX) |
| Formula average | `SUM(V{name}=f{col/N}) > val` |
| Formula percentage | `col > 0 AND V{name}=f{(col*0.2)} > val` |
| IN LIST | `col IN LIST (v1;v2)` |
| Attribute equality | `Profile_Cdr_Handset_Type = smartphone` |
| AON threshold | `AON > 65` |
| GROUP BY | `GROUP BY col` |

### Deduplication (DuplicateSeedError)

`save_reinforced_seed(seed, all_seeds=None)` checks two levels before writing:

- **Level 1 — exact condition**: the `parent_condition` string was already
  reinforced previously (found in `reinforced_seeds.json`).
- **Level 2 — same template**: the derived `output_template` already exists in
  any known seed — catalog, extra_seeds (S134–S148), or reinforced.

Pass the current loaded seed pool as `all_seeds` to enable Level 2:
```python
save_reinforced_seed(seed, all_seeds=seeds)
```

Both violations raise `DuplicateSeedError` (subclass of `ValueError`) with a
message naming the conflicting seed ID and source.

### LangSmith tracing

| Function | Decorator |
|----------|-----------|
| `parse_parent_condition` | `@traceable(name=...)` |
| `make_reinforced_seed` | `@traceable(name=...)` |
| `save_reinforced_seed` | `@traceable(run_type="tool", name=...)` |

### Storage

Reinforced seeds are stored in `DATA_DIR/reinforced_seeds.json` — a plain JSON
array. They are **never written back** into the main catalog JSON.

## 2. Modified — `seeds.py` (`load_seeds()`)

### Source field injection

After merging catalog seeds and `extra_seeds`, every seed in the returned list
now carries a `source` field:

| `source` value | Seeds |
|----------------|-------|
| `"catalog"` | Original catalog seeds (S001–S133 and any others not in `extra_seeds`) |
| `"extra_seed"` | Code-defined seeds S134–S148 |
| `"reinforced"` | Seeds from `reinforced_seeds.json` |

Injection uses `setdefault` for catalog seeds (preserves value if already set)
and hard-sets `"extra_seed"` for all IDs in `extra_seeds`.

### Reinforced seed loading

After the main catalog is saved to disk, `load_seeds()` reads
`DATA_DIR/reinforced_seeds.json` (if it exists), tags each entry
`source = "reinforced"`, and appends them to the returned list.

Reinforced seeds are appended **after** the save, so they are never written
into the main catalog JSON file.

Errors loading `reinforced_seeds.json` (e.g. corrupt JSON) are caught and
printed as warnings — they do not crash the pipeline.

## 3. Modified — `pipeline.py`

### Added import

```python
from langsmith import traceable
```

### New function — `reinforce_from_condition()`

```python
@traceable(name="reinforce_from_condition")
def reinforce_from_condition(
    original_input: str,
    parent_condition: str,
    client_name: str | None = None,
) -> dict:
```

Calls `make_reinforced_seed` → `save_reinforced_seed` → `load_seeds()` (global
reload so the new seed is available to the same process immediately).

Returns:
```python
{
    "ok":       True,
    "seed_id":  "R1746398123456",
    "template": "{date_col} >= CurrentMonth-{N}MONTHS AND ...",
    "message":  "Seed R... saved and catalog reloaded."
}
```

Raises `DuplicateSeedError` (from `reinforcer`) if the seed would duplicate an
existing one.

### Typical two-step workflow

```python
# Step 1 — pipeline fails
result = run_vp_graph("subscribers whose data download is more than 5GB in 3 months")
# result["seed_decision_status"] == "NO_CANDIDATES"

# Step 2 — provide the correct condition
from pipeline import reinforce_from_condition
r = reinforce_from_condition(
    original_input = "subscribers whose data download is more than 5GB in 3 months",
    parent_condition = "COMMON_Event_Date >= CurrentMonth-3MONTHS AND SUM(COMMON_Data_Volume) > 5000",
)

# For graph.py users: reload to update graph._seeds
import importlib, graph
importlib.reload(graph)
from graph import run_vp_graph

# Step 3 — re-run; reinforced seed is found
result2 = run_vp_graph("subscribers whose data download is more than 5GB in 3 months")
```

## 4. Modified — `api_client.py`

### Before

Single-level in-memory dict cache. Wiped on every process restart or
`importlib.reload(api_client)`.

```python
_VP_VERIFY_CACHE: dict[str, tuple[dict, float]] = {}
```

### After — two-level cache (L1 in-memory + L2 SQLite)

```python
_VP_VERIFY_CACHE: dict[str, tuple[dict, float]] = {}  # L1: per-session
_db_conn: sqlite3.Connection | None = None             # L2: persistent
```

**Lookup order in `call_vp_verify()`:**

1. L1 hit (in-memory, no I/O) → return immediately
2. L2 hit (SQLite read, TTL checked) → warm L1, return
3. Miss → call VP_verify API → write to both L1 and L2

**SQLite schema** (`DATA_DIR/vp_verify_cache.db`):

```sql
CREATE TABLE vp_verify_cache (
    condition_text TEXT PRIMARY KEY,
    result_json    TEXT NOT NULL,
    created_at     REAL NOT NULL,   -- Unix timestamp
    expires_at     REAL NOT NULL    -- Unix timestamp
);
```

WAL journal mode is enabled for better concurrent read performance.

**New imports:**
```python
import json
import sqlite3
from config import DATA_DIR   # added alongside VP_VERIFY_URL
```

### Cache management functions

#### `clear_vp_cache(condition_text=None, expired_only=False) → int`

Clears from both L1 and L2. Returns number of SQLite rows removed.

```python
from api_client import clear_vp_cache

# Delete one specific bad/stale entry
clear_vp_cache("recharge count")

# Wipe everything (e.g. after schema change)
clear_vp_cache()

# Prune only entries past their TTL
clear_vp_cache(expired_only=True)
```

#### `inspect_vp_cache() → list[dict]`

Returns all SQLite entries with human-readable timestamps and active/expired
status. Use this to find the exact key string before calling `clear_vp_cache`.

```python
from api_client import inspect_vp_cache

for entry in inspect_vp_cache():
    print(entry)
# {'condition_text': 'recharge count', 'created_at': '2026-05-04 10:30:00',
#  'expires_at': '2026-05-04 11:30:00', 'status': 'active'}
```

#### Changing TTL

```python
import api_client
api_client.VP_VERIFY_CACHE_TTL = 86400  # 24 hours (affects new writes only)
```

#### Direct SQLite access

```bash
sqlite3 data/vp_verify_cache.db

SELECT condition_text, datetime(created_at,'unixepoch'), datetime(expires_at,'unixepoch')
FROM vp_verify_cache;

DELETE FROM vp_verify_cache WHERE condition_text = 'recharge count';
DELETE FROM vp_verify_cache WHERE expires_at <= strftime('%s','now');
```

## 7. Architectural notes added

- **Seed sources are now explicit.** Every seed in the active list has
  `seed["source"]` ∈ `{"catalog", "extra_seed", "reinforced"}`. Useful for
  logging, debugging, and filtering.

- **`reinforced_seeds.json` is the escape hatch.** When the pipeline has no
  matching seed and the user knows the correct condition, they reinforce rather
  than modify `seeds.py` or the catalog JSON.

- **VP_verify cache survives restarts.** SQLite L2 means repeated identical
  queries (same KPI text, same filter phrase) never hit the network after the
  first resolution.

- **Deduplication prevents catalog bloat.** A reinforced seed whose template
  matches an existing catalog seed is rejected with `DuplicateSeedError` instead
  of being silently added as a duplicate.
